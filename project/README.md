# You Are Bot

Проект по курсу ProdML, соревнование [You Are Bot](https://stackmorelayers.ai/competitions/you-are-bot). Нужно по диалогу двух участников предсказать вероятность того, что участник бот. Метрика LogLoss

## Запуск

Нужен [uv](https://docs.astral.sh/uv/), он сам поставит python 3.12 и библиотеки из uv.lock. Данные соревнования (train.json, ytrain.csv, test.json, ytest.csv, sample_submission.csv) надо положить в папку data в корне репозитория

```bash
./run.sh
```

run.sh ставит окружение, потом запускает prepare_data.py (считает признаки) и train.py (кросс-валидация, финальная модель, сабмит). Все параметры лежат в config.yaml, любой можно поменять при запуске:

```bash
./run.sh model=logreg
```

```bash
./run.sh use_text=false depth=6
```

Результаты смотреть в mlflow (из папки project, потом открыть http://127.0.0.1:5000):

```bash
uv run mlflow ui
```

EDA лежит в eda.ipynb, открыть можно так:

```bash
uv run --group eda jupyter lab
```

## Файлы

- config.yaml - все параметры
- features.py - загрузка диалогов и признаки
- prepare_data.py - считает признаки и сохраняет их в data/processed
- train.py - кросс-валидация, обучение, сабмит, логирование в mlflow
- run.sh - запуск всего сразу
- pyproject.toml, uv.lock - зависимости с точными версиями
- eda.ipynb, figures/ - EDA и картинки для презентации

## Что пишется в mlflow

- все параметры из config.yaml и md5 файлов с данными
- коммит git и есть ли незакоммиченные изменения
- logloss на каждом фолде, среднее и std по фолдам, oof auc
- uv.lock, сабмит, график важности признаков
- обученные модели (tf-idf и catboost)

Повторный запуск с теми же параметрами дает те же метрики: seed один на все, версии библиотек зафиксированы

## Решение

Для каждого участника считаются признаки по диалогу:

- эхо: как часто участник дословно повторяет прошлую реплику собеседника, и насколько он на нее похож (jaccard по триграммам)
- структура: кто начал и кто закончил диалог, доля сообщений, сообщения подряд
- стиль: длина, заглавные буквы, пунктуация, markdown, доля кириллицы, слова про ботов

Те же признаки считаются для собеседника (opp_*). В диалоге бывает максимум один бот, поэтому участников логично оценивать вместе

Еще есть текстовая модель: tf-idf по символам и словам + логистическая регрессия. Ее скоры для участника и собеседника идут в catboost как признаки. Чтобы не было утечки, catboost учится на out-of-fold скорах

Валидация StratifiedGroupKFold по dialog_id на 5 фолдов, оба участника диалога всегда в одном фолде

Что пробовал и убрал:

- постобработку "в диалоге не больше одного бота": catboost и так видит собеседника, с ней cv было чуть хуже
- встроенную обработку текста в catboost вместо tf-idf: сильно хуже (0.19) и в разы медленнее
- 45 признаков вместо 22: cv лучше всего на 0.005, это меньше разброса между фолдами, а код сильно проще

| Эксперимент | Запуск | CV LogLoss | OOF AUC |
|---|---|---|---|
| константа (доля ботов) | | 0.676 | 0.5 |
| tf-idf + логрег | ./run.sh model=logreg | 0.462 ± 0.015 | 0.844 |
| catboost без tf-idf | ./run.sh use_text=false | 0.199 ± 0.027 | 0.975 |
| catboost + tf-idf | ./run.sh | 0.136 ± 0.019 | 0.988 |

## Как может выглядеть сервис

```
чат / клиент
    |  POST /predict {dialog_id, messages: [{participant_index, text}, ...]}
    v
FastAPI в docker, при старте грузит модели из mlflow
    |  features.py -> tf-idf -> catboost
    v
[{participant_index: 0, is_bot: 0.03}, {participant_index: 1, is_bot: 0.97}]
    |
    +-> логи запросов -> мониторинг дрифта -> разметка -> переобучение через run.sh
```

Вероятность можно пересчитывать после каждого нового сообщения. Признак "кто написал последнее сообщение" скорее артефакт того, как собирали данные, в реальном сервисе он будет работать по другому
